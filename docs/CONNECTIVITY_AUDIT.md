# 神経接続と感覚・運動カバレッジの監査

この機能は、登録された細胞の割合、配線上の接続、モデル上で非ゼロの重み、
感覚入力の接続、運動出力の割当、実際の発火を別々に数えます。
**いずれの割合も、生物学的再現率や歩行の完成率ではありません。**

## 母集団を混ぜない

現行ロックは `male-cns:v1.0`、166,700登録ニューロン、25,582,938接続行です。
データ契約の815運動ニューロンは全体の約0.489%、残る165,885は約99.511%です。
これは登録数の算術であり、接続済み・活動済み・筋肉と対応済みの割合ではありません。
また「運動ニューロンではない」は「運動に関係しない」という意味ではありません。

別版の公式集計や別の除外条件の分子を、このグラフの分母で割らないでください。
登録数の差を推測で補正したり、数合わせのために細胞や配線を削除したりしません。
詳細なデータ条件と再配布境界は[データの説明](DATA.md)を参照してください。

## 読み取り専用の実データ監査

準備済みのロック一致データがある環境で、リポジトリのCLIを実行します。
基礎集計にはNumPyだけが必要です。Brian2、MuJoCo、FlyGym、GPUは起動しません。

```bash
python fly_effect.py audit-connectivity --graph /path/to/graph --out work/census-01
```

全5ファイルのSHA256を同じ開いたファイル記述子で前後に確認し、IDの一意性、
motor indexの範囲、符号、NPYヘッダーと実payload長、接続レコード長・端点を検査します。
元のグラフ、ロック、受入条件には書き込みません。これはデータの作者認証やOS sandboxではありません。

出力の読み方:

| 出力 | 意味 |
|---|---|
| `registered` | 実ファイルから数えた全登録数、motor registry内外の割合、符号0の割合 |
| `stored` | 接続行数、保存されたcountの総和、count=0行、自己結合行 |
| `layers.structural` | 指定した行count閾値を満たす配線。初期値は1 |
| `layers.nonzero_model_weight` | 上に加え送信側の符号が0ではない配線。抑制性も含む |
| 各layerの`blocks` | 非運動→非運動、非運動→運動、運動→非運動、運動→運動。行数とcount総和を別記 |
| 各layerの`groups` | 全体・motor・非motorごとの入出力、孤立、他ニューロンとの接続、運動ニューロンを直接標的とする割合 |

割合は常に `numerator`、`denominator`、`percent` を保存します。
分母0は `percent: null`。未測定を0%や100%へ変換しません。

`incident`は自己結合を含みます。別の細胞とつながる割合は
`connected_to_other_neurons`です。どちらも「全細胞が同一の連結成分に属する」ことを意味しません。
符号0の細胞の出力はstructuralに存在しても、現行の符号仮説では非ゼロ重みの層に入りません。
非ゼロ重みや抑制性の経路があっても、実際の発火・筋力・行動を保証しません。

接続行はニューロン対の一意な本数と同義ではありません。重複した端点ペアを保持し、
`unique_endpoint_pairs: null`とします。count総和は保存値の集計であって、
電子顕微鏡原画像から個別シナプス接点を再同定した値ではありません。
細胞型別の分類と個々の入力源の実生理は、この監査では未測定です。

## 運動ニューロンまで届く経路

必要なときだけ、追加の逆向き探索を明示的に有効にします。

```bash
python fly_effect.py audit-connectivity --graph /path/to/graph --out work/census-paths-01 --reachability --max-passes 64 --wall-limit 120
```

これは「非運動ニューロンから任意のmotor registry細胞へ有向経路があるか」の測定です。
経路の向きを逆にして、運動ニューロンから到達可能な細胞数を答える処理ではありません。
各走査では前回の到達集合を固定するため、レコード順やチャンク分割で途中結果は変わりません。
到達集合が確定した場合は `exact`、走査回数の上限では `lower_bound` と明示します。
下限しか測れていない層の割合を、正確な到達率として紹介しないでください。
抑制性経路も含むグラフ上の到達可能性であり、運動を誘発できる割合ではありません。

`--min-count 5`は各保存行のcountで選別します。重複ペアを合算した後の5シナプス閾値とは異なります。
比較する実験では閾値、dataset、ロックhash、入力ファイルhashを揃えてください。

全グラフの密行列や全辺CSRを作らず、メモリは登録細胞数＋チャンク行数に比例します。
基礎集計は1回走査、経路探索は最大passes回の追加走査です。初期chunkは250,000行、
上限1,000,000行、wall budgetは120秒です。wall limitは操作間で検査する協調的上限であり、
実行中I/Oの強制終了やRSSのhard capではありません。

出力先は新しいdirectoryに限定します。欠落・不正データ、時間切れはexit 2と失敗receiptにし、
完全な実測としては認定しません。既存の成功結果を上書きせず、別データや人工回路にfallbackしません。

## 身体との接続は別に計数する

実際にEngineを実行した際のreportに、`sensorimotor_coverage`を追加します。
既存のreportフィールドは保持します。

- motor registry全体、歩行対象、歩行対象外、実際のjoint assignment、未割当を別集計。
- 行の実IDと内部index、関節名と実assignment、解剖学的校正flagを検査。
- 全motorの発火を「割当済み・未割当・歩行対象外」に分け、細胞別合計とSpikeMonitorの合計を照合。
- 身体入力に使う実際のsensory ID数と有効/無効設定を記録。これは全生物学的感覚細胞に対するカバー率ではない。

関節へ割り当てただけで解剖学的校正済みにはしません。発火を筋肉側へ渡していても、
十分な力・静的支持・動的保持・歩行が成立したとはしません。
既存の[身体実験](FOOT_PLACEMENT.md)と[受動関節の診断](PASSIVE_CONFLICT.md)、
生物学的受入条件は変更していません。

この追加によりコード識別子は変わります。従来どおり異なるコードのcheckpoint復元は拒否されます。
古いcheckpointのidentityを新しいコードに合わせて書き換えてはいけません。

## 検証範囲

小さな人工グラフ、100種類の固定seedランダムグラフと独立したPython集合/BFS実装、
不正データ、空母集団、循環・抑制性・符号0・自己結合・端点重複・走査打切りを検査します。
runtime reportは合成MotorMapとSpikeMonitor相当の入力で実際のreportメソッドを検査します。
これらは全CNSの新しい実行や動物実験ではありません。
大規模実データは同梱されておらず、取得・加工パイプラインの完成もこの変更では主張しません。

一次仕様: [NumPy NPY形式](https://numpy.org/doc/2.2/reference/generated/numpy.lib.format.html)。
