# リリース

1. 公開先、ライセンス、MAINTAINERSを確定。
2. python -m pytest と python scripts/audit_release.py を実行。
3. クリーンな仮想環境でdoctorと人工回路デモを確認。
4. データ・秘密情報・個人パス・キャッシュが追跡されていないことを確認。
5. python -m build で配布物を作り、内容を確認。
6. CHANGELOGとSTATUSを更新。公開版の確認と過去のローカル結果を分ける。
7. CIを確認してタグを付け、リリースノートへ制限とチェックサムを記載。

安定版の条件が揃うまでpre-alpha/alphaを表示します。データ、モデル、受入、インターフェースの変更に互換性情報を付けます。スキーマやチェックポイントを黙って読み替えません。

公開後はprivate vulnerability reporting、Discussions、mainの保護ルールを設定します。少なくともCIを必須にし、運営人数が増えたら独立レビューを必須にします。未設定の機能を有効だと表記しません。

CIは自動公開やPyPIアップロードを行いません。リリース判断はメンテナーが行います。
